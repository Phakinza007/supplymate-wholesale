# Step 8 — Playwright E2E Test Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire up a Playwright E2E suite, run against a local Supabase stack, covering the golden
path (register → browse → cart → checkout → slip upload → admin verifies/ships/completes → customer
sees final status) plus two security checks (non-admin denied `/admin`, cross-user payment-slip
access denied).

**Architecture:** `@playwright/test` under `e2e/`, config at `playwright.config.ts`. An npm
`pretest:e2e` hook starts the local Supabase stack and resets its DB (re-applying migrations +
`seed.sql`) before every run, so each run starts from a known-clean DB. Playwright's `webServer`
auto-starts `vite --mode e2e`, reading a generated `.env.e2e.local` that points the app at the
**local** stack's URL/anon key (never the hosted dev project). Two shared helper modules
(`e2e/helpers/auth.ts`, `e2e/helpers/checkout.ts`) factor out the repeated
signup/login/buy-and-upload-slip flow so the golden-path and security specs don't duplicate it.

**Tech Stack:** `@playwright/test`, `supabase` (CLI, as a devDependency), `dotenv`,
`@supabase/supabase-js` (already a dependency, reused directly in the security spec for the
Node-side cross-user API check).

## Global Constraints

- `supabase/seed.sql` is local-dev-only, applied via `supabase db reset` — never run against a
  hosted project. This plan's suite runs exclusively against the local stack (`supabase start`).
- **Discovered while reading the actual seed data (not assumed from the design spec): `seed.sql`
  already creates two ready-to-use accounts** — `admin@example.com` / `password123` (pre-promoted
  to `role = 'admin'`) and `customer@example.com` / `password123` (has 4 pre-existing orders in
  `pending`/`verified`/`shipped`/`done` status and one saved address). **This plan uses
  `admin@example.com` directly for the admin half of the golden path — no admin-promotion helper,
  no direct Postgres connection, and no `pg` dependency are needed**, simplifying the design spec's
  original architecture (which assumed no seeded admin existed). The golden-path and security specs
  still sign up **fresh** customer accounts via the real UI rather than reusing
  `customer@example.com`, so each test's order/address state stays isolated from the seeded rows.
- No CI workflow is added — `npm run test:e2e` is a local/manual suite only, per the approved
  design spec.
- Exact, verbatim UI strings/selectors this plan's tasks depend on (from reading the current
  source, not guessed):
  - `SignupPage`: fields `#fullName`, `#email`, `#password`; submit button text `"Sign up"`; on
    success (local stack has `enable_confirmations = false`) navigates to `/`.
  - `LoginPage`: fields `#email`, `#password`; submit button text `"Log in"`; on success navigates
    to `/` (or `location.state.from`).
  - `AddressBookPage` / `AddressForm`: list page has an `"Add address"` button; form fields
    `#recipient_name`, `#phone`, `#line1`, `#line2`, `#subdistrict`, `#district`, `#province`,
    `#postal_code` (only `recipient_name`/`phone`/`line1`/`province`/`postal_code` are `required`);
    submit button text `"Save address"`.
  - `ProductListPage`: product links match `a[href^="/products/"]`.
  - `ProductDetailPage`: `"Add to cart"` button; on click shows `"Added ✓"` for ~2s.
  - `CartPage`: `"Proceed to checkout"` link to `/checkout`.
  - `CheckoutPage`: with ≥1 saved address, the first auto-selects; `"Place order"` button; on
    success navigates to `/orders/:orderId`.
  - `OrderDetailPage` (customer): heading `Order #{order_number}`; status text is exactly
    `Status: {status}` (lowercase status value, e.g. `Status: pending`); pending+no-slip shows a
    bare `<input type="file">` and a `"Upload payment slip"` button; after upload shows
    `"Payment slip received — we'll verify it shortly."`; any non-pending status shows
    `"This order is {status}."`.
  - `AdminOrderListPage`: each row is a `Link` to `/admin/orders/:orderId` with text
    `Order #{order_number} · {customer_name}`.
  - `AdminOrderDetailPage`: status text `Status: {status}`; `"Verify payment"` button (disabled
    until a slip exists); on `verified` status shows `#tracking` / `#carrier` inputs and a
    `"Mark as shipped"` button, plus a `"Reject slip (request re-upload)"` button; on `shipped`
    status shows a `"Mark as done"` button; `"Cancel order"` reveals `#cancel-reason` +
    `"Confirm cancel"` / `"Never mind"`.
  - `AdminRoute`: unauthenticated → redirect to `/login`; authenticated non-admin → redirect to `/`.
- `vite.config.ts` aliases `@` → `./src`; `tsconfig.app.json` only includes `src`, so `e2e/**` is
  outside the app's typecheck/build — adding it introduces no risk to `npm run build`/`typecheck`
  or `scripts/check-core-boundary.mjs`.
- `.gitignore` already ignores `.env.*.local` and has a Playwright section
  (`/test-results/`, `/playwright-report/`, `/playwright/.cache/`) — no `.gitignore` changes needed
  as long as the generated env file is named `.env.e2e.local` (matches the existing `.env.*.local`
  pattern, so it's never committed).

- [ ] **Step 5: Write `scripts/write-e2e-env.mjs`**

```js
#!/usr/bin/env node
// Generates .env.e2e.local from the running local Supabase stack's own status output, so the
// E2E suite never hardcodes a URL/key that could drift from what `supabase start` actually
// produces on this machine or this CLI version.
import { execSync } from 'node:child_process'
import { writeFileSync } from 'node:fs'

const output = execSync('npx supabase status -o env', { encoding: 'utf-8' })

function extract(key) {
  const match = output.match(new RegExp(`^${key}="?([^"\n]*)"?$`, 'm'))
  if (!match) {
    throw new Error(
      `Could not find ${key} in \`supabase status -o env\` output. Full output:\n${output}`,
    )
  }
  return match[1]
}

const apiUrl = extract('API_URL')
const anonKey = extract('ANON_KEY')

writeFileSync(
  '.env.e2e.local',
  `VITE_SUPABASE_URL=${apiUrl}\nVITE_SUPABASE_ANON_KEY=${anonKey}\n`,
)
console.log(`Wrote .env.e2e.local (VITE_SUPABASE_URL=${apiUrl})`)
```

Update the `extract('API_URL')` / `extract('ANON_KEY')` calls if Step 4 found different key names.

import type { Page } from '@playwright/test'

export async function addAddress(
  page: Page,
  opts: { recipientName: string; phone: string; line1: string; province: string; postalCode: string },
): Promise<void> {
  await page.goto('/account/addresses')
  await page.getByRole('button', { name: 'Add address' }).click()
  await page.locator('#recipient_name').fill(opts.recipientName)
  await page.locator('#phone').fill(opts.phone)
  await page.locator('#line1').fill(opts.line1)
  await page.locator('#province').fill(opts.province)
  await page.locator('#postal_code').fill(opts.postalCode)
  await page.getByRole('button', { name: 'Save address' }).click()
  await page.getByText(opts.recipientName).waitFor()
}

export async function buyFirstProductAndUploadSlip(
  page: Page,
  slipPath: string,
): Promise<{ orderUrl: string; orderHeading: string }> {
  await page.goto('/shop')
  await page.locator('a[href^="/products/"]').first().click()
  await page.getByRole('button', { name: 'Add to cart' }).click()
  await page.getByText('Added ✓').waitFor()

  await page.goto('/cart')
  await page.getByRole('link', { name: 'Proceed to checkout' }).click()
  await page.getByRole('button', { name: 'Place order' }).click()
  await page.waitForURL(/\/orders\/.+/)

  const orderHeading = (await page.getByRole('heading', { name: /^Order #/ }).textContent())!.trim()

  await page.locator('input[type="file"]').setInputFiles(slipPath)
  await page.getByRole('button', { name: 'Upload payment slip' }).click()
  await page.getByText("Payment slip received").waitFor()

  return { orderUrl: page.url(), orderHeading }
}
```

import path from 'node:path'
import { fileURLToPath } from 'node:url'
import { test, expect } from '@playwright/test'
import { signUp, logIn, uniqueEmail } from './helpers/auth'
import { addAddress, buyFirstProductAndUploadSlip } from './helpers/checkout'

const __dirname = path.dirname(fileURLToPath(import.meta.url))
const SLIP_PATH = path.join(__dirname, 'fixtures', 'payment-slip.pdf')

test('golden path: register, buy, pay, admin fulfills, customer sees done', async ({ browser }) => {
  const customerContext = await browser.newContext()
  const customerPage = await customerContext.newPage()

  await signUp(customerPage, {
    fullName: 'Golden Path Customer',
    email: uniqueEmail('golden-customer'),
    password: 'password123',
  })

  await addAddress(customerPage, {
    recipientName: 'Golden Path Customer',
    phone: '0891234567',
    line1: '99 Test Street',
    province: 'Bangkok',
    postalCode: '10110',
  })

  const { orderUrl, orderHeading } = await buyFirstProductAndUploadSlip(customerPage, SLIP_PATH)
  await expect(customerPage.getByText('Status: pending')).toBeVisible()

  const adminContext = await browser.newContext()
  const adminPage = await adminContext.newPage()
  await logIn(adminPage, { email: 'admin@example.com', password: 'password123' })

  await adminPage.goto('/admin/orders')
  await adminPage.getByText(orderHeading).click()
  await adminPage.waitForURL(/\/admin\/orders\/.+/)

  await adminPage.getByRole('button', { name: 'Verify payment' }).click()
  await expect(adminPage.getByText('Status: verified')).toBeVisible()

  await adminPage.locator('#tracking').fill('TH1234567890')
  await adminPage.locator('#carrier').fill('Thailand Post')
  await adminPage.getByRole('button', { name: 'Mark as shipped' }).click()
  await expect(adminPage.getByText('Status: shipped')).toBeVisible()

  await adminPage.getByRole('button', { name: 'Mark as done' }).click()
  await expect(adminPage.getByText('Status: done')).toBeVisible()

  await customerPage.goto(orderUrl)
  await expect(customerPage.getByText('This order is done.')).toBeVisible()

  await customerContext.close()
  await adminContext.close()
})
```

- [ ] **Step 1: Write `e2e/security.spec.ts`**

```ts
import path from 'node:path'
import { fileURLToPath } from 'node:url'
import { test, expect } from '@playwright/test'
import { createClient } from '@supabase/supabase-js'
import { signUp, uniqueEmail } from './helpers/auth'
import { addAddress, buyFirstProductAndUploadSlip } from './helpers/checkout'
import type { Database } from '../src/lib/database.types'

const __dirname = path.dirname(fileURLToPath(import.meta.url))
const SLIP_PATH = path.join(__dirname, 'fixtures', 'payment-slip.pdf')

test('non-admin is denied /admin', async ({ page }) => {
  await signUp(page, {
    fullName: 'Plain Customer',
    email: uniqueEmail('plain-customer'),
    password: 'password123',
  })

  await page.goto('/admin')
  await page.waitForURL('/')
  await expect(page).toHaveURL('/')
})

test("a user cannot read another user's payment slip", async ({ page }) => {
  const emailA = uniqueEmail('customer-a')
  const emailB = uniqueEmail('customer-b')
  const password = 'password123'

  await signUp(page, { fullName: 'Customer A', email: emailA, password })
  await addAddress(page, {
    recipientName: 'Customer A',
    phone: '0891111111',
    line1: '1 Test Street',
    province: 'Bangkok',
    postalCode: '10110',
  })
  const { orderUrl } = await buyFirstProductAndUploadSlip(page, SLIP_PATH)
  const orderId = new URL(orderUrl).pathname.split('/').pop()!

  const supabaseUrl = process.env.VITE_SUPABASE_URL!
  const anonKey = process.env.VITE_SUPABASE_ANON_KEY!

  // Sign in as A directly (Node-side) to read back A's own slip path -- the exact value
  // attach_payment_slip() wrote, not a guess at the upload path's naming scheme.
  const clientA = createClient<Database>(supabaseUrl, anonKey)
  const { error: signInAError } = await clientA.auth.signInWithPassword({ email: emailA, password })
  expect(signInAError).toBeNull()

  const { data: orderRow, error: orderRowError } = await clientA
    .from('orders')
    .select('payment_slip_path')
    .eq('id', orderId)
    .single()
  expect(orderRowError).toBeNull()
  const slipStoragePath = orderRow!.payment_slip_path
  expect(slipStoragePath).toBeTruthy()

  // Customer B: independent account, created directly via the API (no UI signup needed here --
  // the signup UI itself is already covered by the golden-path and "non-admin" specs).
  const clientB = createClient<Database>(supabaseUrl, anonKey)
  const { error: signUpBError } = await clientB.auth.signUp({
    email: emailB,
    password,
    options: { data: { full_name: 'Customer B' } },
  })
  expect(signUpBError).toBeNull()

  const { data: signedUrlData, error: signedUrlError } = await clientB.storage
    .from('payment-slips')
    .createSignedUrl(slipStoragePath!, 60)

  expect(signedUrlError).toBeTruthy()
  expect(signedUrlData).toBeNull()
})
```
